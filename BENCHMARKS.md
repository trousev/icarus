# BENCHMARKS.md — как мерить математику

Короткая рабочая инструкция: что гоняем, какими командами, чем сверяем и что
считать результатом. Обзор бенчмарков и обоснование выбора — `research/08-ai-math-benchmarks.md`
и `research/09-startovyy-test.md`; числа контрольного прогона — `research/10-baseline-deepseek-flash.md`.

Стенд — `packages/math-eval`. Он не входит в `./script/test`: тесты пакета гоняются
в CI и не требуют ни сети, ни ключей, а вот сами прогоны стоят денег и времени,
поэтому запускаются руками.

## Что меряем

**ASyMOB** — 35 368 задач чистой символьной манипуляции: интегралы, ОДУ, ряды,
пределы, гипергеометрия. Берём только **возмущённые семейства**: сид-набор
(`Original`, 100 задач) топ-модели проходят на ~97%, мерить там нечего. Возмущения
добавляют буквенные параметры, длинные числа и подстановки вида
`sin²(−Ax)+cos²(Ax)` — тот, кто узнал шаблон, ломается.

Три руки, и путать их нельзя:

| рука | как запускается | что измеряет |
|---|---|---|
| **чистая модель** | `--target model`, провайдер напрямую | потолок модели без обвязки; только этим числом можно сверяться с публикацией |
| **Икар без Maple** | `--target icarus`, в `config.yaml` нет MCP `maple` | вклад агентской обвязки |
| **Икар с Maple** | `--target icarus`, MCP `maple` включён | исходный вопрос: сколько даёт Maple |

## Промпт: три режима, и это не мелочь

Сэмплер умеет `--prompt <nocode|tools|maple>`:

- `nocode` — формулировка ASyMOB, их же запрет на код. Единственный режим,
  сравнимый с публикацией, **но для руки Икара он не годится**: агент честно
  подчиняется человеку и не зовёт Maple вообще (проверено: 0 вызовов на 10
  задачах), так что «Икар + Maple» превращается в «Икар без Maple»;
- `tools` — инструменты разрешены, про Maple ни слова. Агент сам решает и зовёт
  Maple в 91% задач. Это и есть «Maple в кармане» — рабочий режим для руки Икара;
- `maple` — прямая инструкция считать через Maple: если нужно проверить, что
  агент вообще способен им пользоваться.

Задача во всех трёх режимах одна и та же, меняется только разрешение на инструменты.

## Предусловия

```bash
# ключ провайдера (лежит в .env в корне)
grep -c DEEPSEEK_API_KEY .env

# грейдер: math-verify в отдельном окружении (в системный питон не встанет — PEP 668)
python3 -m venv runtime/math-eval/venv
runtime/math-eval/venv/bin/pip install math-verify

# данные ASyMOB (CC BY-SA 4.0, в git не хранятся)
mkdir -p runtime/math-eval/datasets
curl -sL -o runtime/math-eval/datasets/Full_ASyMOB_Dataset.json \
  "https://huggingface.co/datasets/Shalyt/ASyMOB-Algebraic_Symbolic_Mathematical_Operations_Benchmark/resolve/main/Full_ASyMOB_Dataset.json"
```

Для руки Икара дополнительно: поднятый стек (`./script/server -d`), `MAPLE_DIR` с
Maple 18 и apiKey из `config.yaml`.

## Прогон

```bash
# 1. сэмпл: 400 задач, стратифицированно по семействам, сиды исключены.
#    Зерно фиксирует состав — то же зерно даёт тот же набор.
node packages/math-eval/src/asymob.ts --total 400 --seed asymob-1 \
  --out runtime/math-eval/suites/asymob-400.jsonl

# 2. контрольная рука: чистая модель, без Икара и инструментов.
set -a && . ./.env && set +a
node packages/math-eval/src/run.ts --target model \
  --provider-url https://api.deepseek.com/v1 --provider-model deepseek-flash \
  --suite runtime/math-eval/suites/asymob-400.jsonl --tier all \
  --concurrency 6 --arm deepseek-flash-400 --out runtime/math-eval/runs/model-400

# 3. разметка и сводка (быстро: секунды, спасибо пулу процессов).
runtime/math-eval/venv/bin/python packages/math-eval/grader/asymob_grade.py --jobs 6 \
  --results  runtime/math-eval/runs/model-400/results.jsonl \
  --suite    runtime/math-eval/suites/asymob-400.jsonl \
  --manifest runtime/math-eval/suites/asymob-400.manifest.json \
  --out      runtime/math-eval/runs/model-400 --label "DeepSeek Flash, 400"
runtime/math-eval/venv/bin/python packages/math-eval/grader/asymob_summary.py \
  --graded runtime/math-eval/runs/model-400/graded.jsonl \
  --out    runtime/math-eval/runs/model-400 --label "DeepSeek Flash"
```

Рука Икара — та же команда `run.ts` с `--target icarus --key <apiKey> --user probe
--maple-dir runtime/users/probe/maple` (каталог журналов Maple; по нему считается,
сколько раз агент реально позвал движок). Грейдер тот же: **Maple из сверки не
участвует** — он инструмент агента, а не судья бенчмарка.

Артефакты прогона: `results.jsonl` (по строке на задачу, пишется потоком),
`summary.md`, `graded.jsonl`, `graded.md`, `summary-benchmark.md`.

## Что считать результатом

Три числа, и все три публикуются:

- **сырая точность** — по нашему сэмплу;
- **строгая** — только символьное тождество, без послаблений (нижняя граница);
- **пересчёт на доли полного набора** — главное число для сравнения со статьёй.

Пересчёт обязателен: сэмпл сбалансирован по семействам, а полный ASyMOB — нет
(Equivalence 55%, Numeric 41%, Symbolic 4%). Сырые проценты с «Total» статьи
несравнимы.

Контрольный прогон (чистый `deepseek-flash`, 400 задач, сентябрь 2026): 63.8%
сырых, 24.2% строгих, **75.9% в пересчёте**. Ориентиры статьи: средняя по
конфигурациям 46.8%, DeepSeek-V3 45.4%, DeepSeek-R1 78.3%. Если новая рука
получает число сильно вне этой полосы — сначала проверяем стенд, а не радуемся.

## Правила сверки (и почему так)

Эталон вариантов лежит только в синтаксисе SymPy, поэтому грейдер отдельный:
SymPy + `math-verify` для разбора LaTeX. Тонкости, каждая — из реальных прогонов:

- `e` в ASyMOB — число Эйлера (в SymPy `e` — свободный символ), поэтому
  подставляется `E`;
- `y(x)=…` — обёртка, снимается; `+C` у неопределённых интегралов убирается,
  если `C` нет в эталоне;
- если символьное сравнение не сходится, ответ проверяется численно на случайных
  рациональных точках; «лишние» параметры приравниваются к 1 — это правило самой
  ASyMOB («подстановка 1 возвращает исходную задачу»), отключается `--no-anchor`;
- эталоны со степенями вида `87789722**(-65316278)` (полмиллиарда знаков) не
  считаются ничем: такие задачи помечаются «сравнить не удалось» и идут в
  нерешённые — оценка снизу. Попытка их посчитать вешает SymPy намертво.

## Чего не делать

- **Не грейдить руку чистой модели через Maple** и вообще не тащить Maple в
  сверку: он инструмент агента, а не арбитр бенчмарка. Сравнение с публикацией
  возможно только на SymPy-методологии.
- **Не брать сиды ASyMOB** и не смешивать их с возмущениями: сиды протухли.
- **Не сравнивать сырые проценты с «Total» статьи** — только пересчёт.
- **Не запускать два прогона в один `--out`**: второй обнулит `results.jsonl`.
- **Не менять `--seed` между руками**: сравнивать можно только один и тот же
  набор задач.
- **Не сравнивать руки с разным `--concurrency`** по времени: на точность
  параллельность не влияет, на латентность влияет.

## Если сломалось

| симптом | причина |
|---|---|
| `провайдер не ответил` / 401 | нет или протух ключ: `--provider-key` или `DEEPSEEK_API_KEY` в `.env` |
| `Икар не отвечает на …/healthz` | стек не поднят: `./script/server -d`, либо `--skip-health` |
| `pip: externally-managed-environment` | ставить только в venv (`python3 -m venv`), в системный питон не надо |
| грейд висит минутами | эталон с астрономической степенью: проверь `astronomical_text`, это защита, а не баг |
| `ответ не разобран` | модель ответила не в математическом окружении: смотри `results.jsonl`, обычно лечится просьбой `\boxed{}` в промпте |
| все задачи «не сошлось», а `extracted` пустой | сломан разбор ответа, а не модель: смотри `content` в `results.jsonl` |

## Цена

400 задач на `deepseek-flash`: ~1.9 млн токенов (меньше доллара), медиана ответа
10 с, весь прогон при `--concurrency 6` — около часа. Разметка — секунды.
