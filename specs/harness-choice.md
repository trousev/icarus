# Второй движок: Claude Code рядом с pi

> Статус: дизайн + пробник, адаптера в сервисе ещё нет. Измерения — 2026-11-09,
> песочница, Claude Code 2.1.319, `deepseek-chat` через
> `https://api.deepseek.com/anthropic`. Воспроизведение — `tools/harness-probe/`.

## Коротко

Claude Code **работает** как headless-движок поверх Anthropic-совместимого эндпоинта:
одна реплика, инструменты, стрим и финальный `result` — всё есть, ход занимает секунды.
Его поток **не совпадает** с pi, но переводится в наши события одним файлом
(`tools/harness-probe/parse.mjs`): `text`, `step`, `step-update`, `step-end`, `done`,
плюс новое `engine` — «кто отвечает». Второй рендерер панели не нужен.

Дорого не «подключить модель», а **сохранить наше окружение**: история разговоров сейчас
читается из файлов сессий pi, память и MCP разложены по форматам pi, расширения (персона,
экстрактор памяти, эскалация, субагенты) — это API pi, а не наш. Поэтому в один PR это не
влезает: здесь спека, пробник и тесты; адаптер — следующими шагами (раздел «План»).

Решение по развилкам, которое предлагаю:

| вопрос | решение |
|---|---|
| где выбор движка | **у разговора**, поле `engine` в `ChatRecord`; дефолт — `pi` |
| смена посреди треда | только явно: новая эпоха сессии с бейджем движка; молчаливой подмены нет |
| память | каталоги те же; карта окружения рендерится в `AGENTS.md` **и** `CLAUDE.md` из одного источника |
| MCP | наш `mcp.json` → `--mcp-config`; lazy-режим у Claude Code не воспроизводится (см. «MCP») |
| расширения pi | не переиспользуются; персона — системным промптом, остальное — отдельные решения |
| история | пишем свой транскрипт из нормализованных событий, а не читаем файлы Claude Code |
| приватный режим | `--tools`/`--disallowedTools` + `--restricted`; точные deny-правила надо проверить |

## Что измерено

Пробник (`tools/harness-probe/probe.mjs`) запускает `claude --bare -p --input-format
stream-json --output-format stream-json --include-partial-messages` в изолированном `HOME`
и складывает `raw.jsonl`, `turn.jsonl`, `summary.json`, `report.html`.

| прогон | режим | результат | время | что проверяли |
|---|---|---|---|---|
| текст | `--bare`, чистый HOME | `"CLEAN-OK"` | 2.2 с (API 2.0 с) | эндпоинт и auth вообще работают |
| инструмент | `--bare --allowedTools Read` | `"МАЯК-42"`, 1 вызов `Read` | 2.8 с, первый event 0.19 с, `result` 2.73 с | tool_use → tool_result → ответ |
| два хода | `--input-format stream-json`, stdin не закрыт | `"ПЕРВЫЙ"`, затем `"ВТОРОЙ"` в том же процессе | 1.7 с и 2.5 с | один процесс на разговор, как у pi |
| плохой ключ | тот же режим | `result` не пришёл за 90 с, ретраи | — | таймаут и «нет result» — это ошибка |
| `--bare` | `ANTHROPIC_API_KEY` | `"BARE-OK"`, 3 инструмента | 1.2 с | изоляция без плагинов человека |

Расход на прогон с `Read`: вход 1 380 токенов (из них 1 152 кэш), выход 99, два хода
модели. `result.total_cost_usd` = `$0.0077`, но `costBasis: unknown`: Claude Code считает
по прайсу Anthropic. Для DeepSeek это не наши деньги — бюджет считаем по токенам.

Что ещё видно руками:

- `system:init` — единственное место, где лежит список инструментов, режим прав и id
  сессии; `--bare` оставляет `Bash`, `Edit`, `Read` (три! `Write` нет);
- без `--bare` в том же окружении загрузились **53 инструмента**: плагины человека
  (`chrome-devtools`, `browsermcp`, `deepseek-vision`) и их хуки. В `system:init` прилетает
  `slash_commands` из чужих плагинов. Для сервиса это недопустимо;
- `~/.claude/settings.json` **переопределяет** `ANTHROPIC_BASE_URL` из окружения: прогон,
  который выглядел как «против DeepSeek», на деле шёл в локальный прокси. Отсюда
  обязательный чистый `HOME`;
- модель `deepseek-chat` Claude Code не знает и пишет
  `[claude-code:unrecognized_model]` в stderr, но не мешает;
- `modelUsage.contextWindow = 200000`, `maxOutputTokens = 32000`.

## Как сервис говорит с pi сейчас

```
registry.acquire(user, chat, workspace, artifact)
  └─ PiSession (sessions/pi-session.ts)
       ├─ RpcClient (sessions/rpc-client.ts): docker exec -i … pi --mode rpc
       │    JSONL по stdio, запросы с id, события без id
       └─ onEvent → control/chat.ts: case message_update/tool_execution_*/agent_settled
                         └─ hub (control/chat-live.ts): text / step / step-update /
                            step-end / notice / reauth / done / error
                                  └─ chat-client.js: рисует ленту
```

Движок протекает в сервис в четырёх местах:

1. **Запуск** (`piArgsFor`, `modelEnv`): `--mode rpc`, `--session-dir`, `--session-id`,
   `--model provider/id`, `--thinking`, `--no-extensions`, `--exclude-tools` для приватного.
2. **Команды**: `prompt`, `abort`, `clear_queue`, `compact`, `new_session`, `get_state`,
   `get_messages`, `get_session_stats`, `get_commands` — у Claude Code аналогов меньше.
3. **История**: `control/chat.ts:readMessages` читает JSONL сессии pi (роль, content-блоки,
   toolCallId). Это формат pi, не наш.
4. **Окружение**: `AGENTS.md`, `~/.pi/agent/{auth,models,settings,mcp}.json`, каталог
   сессий, env `ICARUS_*` для расширения-персоны.

Вывод: «второй движок» — это не замена `pi` в одном месте, а второй набор из этих четырёх
точек. Поэтому интерфейс должен быть узким и повторять то, что сервис уже делает, а не
изобретать «провайдера агентов».

## Claude Code как движок

### Процесс и протокол

```bash
claude --bare -p \
  --input-format stream-json --output-format stream-json --include-partial-messages \
  --model deepseek-chat --max-turns 4 \
  --allowedTools Read --tools Read,Bash \
  --no-session-persistence --session-id <uuid>
```

- Вход — JSONL в stdin: `{"type":"user","message":{"role":"user","content":[{"type":"text","text":"…"}]}}`.
  Процесс **не завершается** после `result`, пока открыт stdin: второй ход можно послать в
  тот же процесс (проверено). Это прямой аналог `RpcClient` и одна сессия на разговор.
- Выход — JSONL: `system:init`, `stream_event` (Anthropic SSE), `assistant`, `user`
  (tool_result), `result`.
- `--resume <session-id>` и `--session-id <uuid>` дают переживание рестарта сервиса, но id
  обязан быть UUID — из `conversationId` его надо выводить детерминированно.
- `abort` в протоколе ввода **не найден**: у pi есть `{"type":"abort"}`, у Claude Code в
  stream-json его нет. Варианты: SIGTERM процессу (теряем ход, контекст восстанавливаем
  `--resume`), либо control-запрос SDK, которого нет в документированном CLI. Это первый
  открытый вопрос для адаптера; в спеке закладываю «SIGTERM + resume на следующий ход»,
  пока не измерено обратное.

### Формат событий

| что | pi | Claude Code | наше событие |
|---|---|---|---|
| старт | `agent_start` | `system:init` | `engine` (новое) |
| текст | `message_update.text_delta` | `stream_event` → `content_block_delta.text_delta` | `text` |
| шаг | `tool_execution_start` | `stream_event` → `content_block_start.tool_use` | `step` |
| аргументы/прогресс | `tool_execution_update` (есть) | `input_json_delta` (аргументы), прогресса нет | `step-update` |
| итог шага | `tool_execution_end` | `user` → `tool_result` | `step-end` |
| конец хода | `agent_settled` | `result:success` | `done` |
| ошибка | `error` / `extension_error` | `result.is_error` / `subtype` | `error` |
| размышления | `thinking_delta` | `thinking_delta` (если включены) | `thinking` (панель не рисует) |

Чего у Claude Code нет и что нельзя притворить:

- **прогресса инструмента** (`tool_execution_update`): поток вывода bash не приходит;
  `step-update` — это досылка аргументов, а не живой вывод;
- **`extension_error`**: ошибки хуков/плагинов — это `system:hook_*`, они не относятся к
  ходу; в `--bare` их нет;
- **`compact` как команды**: авто-сжатие у Claude Code своё (`--autocompact`), ручного
  «сожми сейчас» в протоколе нет;
- **`new_session`**: новый процесс (или `--session-id` с новым UUID);
- **`get_commands`**: список слэш-команд приходит в `system:init.slash_commands`, но это
  команды Claude Code, а не наши скиллы/промпты.

### Изоляция (обязательно)

1. `HOME` — отдельный каталог на прогон/пользователя; иначе `settings.json` человека
   диктует эндпоинт, плагины и хуки.
2. `--bare` — без хуков, плагинов, автоподхвата `CLAUDE.md`, keychain, auto-memory.
3. `--strict-mcp-config` + `--mcp-config` — только наши серверы.
4. `--no-session-persistence` или отдельный каталог сессий; чужие сессии не читаем.
5. Версия CLI пинится (как `PI_VERSION` в Dockerfile): флаги и события — контракт,
   который ломается между версиями. В этом срезе — 2.1.319.

`--bare` — не «режим для всех»: он режет и полезное (автопамять, `CLAUDE.md`). Для сервиса
это как раз то, что нужно: окружение задаём мы, а не машина человека.

## Адаптер

Не абстракция «на будущее», а узкий контракт ровно под то, что делает `PiSession`:

```ts
interface TurnEngine {
  readonly engine: 'pi' | 'claude-code';
  readonly generation: number;          // скиллы/настройки не переживают смену
  prompt(text: string, images: Image[]): Promise<void>;
  onEvent(listener: (event: EngineEvent) => void): () => void;
  abort(): Promise<boolean>;
  dispose(): void;
  // дальше по мере надобности, не «на всякий случай»:
  // compact?(): Promise<CompactResult>; getMessages?(): Promise<Message[]>;
}
```

`EngineEvent` — наши события, а не сырые. Для pi их уже производит `chat.ts` (он читает
pi-события), но чтобы адаптер был симметричным, разбор pi-событий стоит спустить в
`PiSession`/адаптер, а `chat.ts` оставить потребителем `text/step/step-end/done`. Это
отдельный рефакторинг, без изменения поведения (тесты `chat-*.test.ts` — страховка).

`ClaudeSession`:

1. спавнит CLI в контейнере пользователя (как `docker exec -i … claude …`), с чистым
   `HOME` внутри `/workspaces/.icarus/claude/<user>/home`;
2. держит процесс на разговор, шлёт реплики в stdin, читает JSONL;
3. гоняет строки через `parse.mjs` (тот же, что в пробнике) и отдаёт наши события;
4. при `result` с `is_error` — `error`; при отсутствии `result` за таймаут — `error`, а
   не пустой успех; процесс гасится, следующий ход — `--resume` по id;
5. пишет транскрипт (см. «История») и отдаёт `engine` в первом событии хода.

Чего в адаптере быть не должно: эмуляции pi-RPC поверх Claude Code, парсинга TUI/PTY,
подмены `ANTHROPIC_BASE_URL` через MITM и «прокси-переходников», которые притворяются
Anthropic API. Мы говорим с провайдером тем же протоколом, что и CLI, а не ломаем его.

## Память, workspace, MCP, расширения

### Память и workspace

Каталоги не меняются: `/workspaces/<slug>`, `/workspaces/.icarus/{memory,shared-memory}`,
`incoming/`, `artifacts/`. Меняется только то, **как агент узнаёт карту окружения**:

- сейчас `AGENTS.md` (рендерит `workspace.ts`) и `--mode rpc` в workspace;
- Claude Code читает `CLAUDE.md` из cwd и родителей, но `--bare` это отключает. Значит
  карту подаём явно: `--append-system-prompt` текстом (тот же рендер, что `AGENTS.md`) или
  файлом, если версия поддерживает `--append-system-prompt-file`;
- альтернатива — писать `CLAUDE.md` рядом с `AGENTS.md` из одного рендера. Плюс: файл
  виден человеку и переживает ручную правку; минус: два файла надо держать синхронными.
  Предлагаю **один рендер, две записи** и тест, что содержимое совпадает, кроме заголовка.

Память остаётся файлами: Claude Code умеет `Read/Write/Edit/Bash` в workspace, а
`/workspaces/.icarus/memory` монтируется так же. Автоизвлечение памяти — это наше
pi-расширение, у Claude Code аналога нет (его auto-memory мы отключаем `--bare`).

### История — главная цена

Панель строит ленту из файла сессии pi (`readMessages`): роль, content-блоки,
`toolCallId`. У Claude Code своя сессия в `~/.claude/projects/<cwd>/<uuid>.jsonl`, свой
формат, и он не наш контракт. Варианты:

1. парсить файлы Claude Code — быстро, но это чужой нестабильный формат; при обновлении
   CLI история поедет;
2. **писать свой транскрипт** из нормализованных событий: `<dataDir>/users/<id>/engines/
   claude/<conversation>.jsonl` — те же поля, что у pi-сессии, плюс `engine`. Лента и
   поиск читают его наравне с pi. Дороже на один writer, зато формат наш.

Предлагаю (2). Тогда смена движка посреди треда не рвёт ленту: старые сообщения остаются
с бейджем `pi`, новые — `claude-code`, а «контекст для модели» у каждого движка свой.
Переносить контекст автоматически нельзя: у Claude Code нет импорта pi-сессии, а
пересказ — это отдельный ход модели. Для MVP — новая эпоха с явной пометкой; «передай
эстафету» (сводка старым движком → системная заметка новому) — следующий шаг.

### MCP

Наш `~/.pi/agent/mcp.json` — формат `pi-mcp-extension` (`mcpServers`, `lifecycle`,
`toolPrefix`). Claude Code понимает `--mcp-config` с `mcpServers`:

- stdio: `command`, `args`, `env` — переводится;
- http: `url`, `headers` — переводится, включая наш прокси-ключ для OAuth
  (`/mcp-proxy/<key>`), если Claude Code шлёт заголовки на каждый запрос;
- **lazy** (`mcp_connect`) у Claude Code нет: серверы стартуют при запуске процесса. Для
  ленивых серверов это лишний контекст и лишние процессы; придётся либо запускать их
  только по требованию (отдельный процесс/тулза), либо смириться и грузить сразу.

Точный синтаксис `--mcp-config` и поведение заголовков в этом срезе **не проверяли** —
это следующий пробник, до адаптера.

### Расширения

`packages/extensions` — это API pi, а не наш. Что с ними:

| расширение | судьба при втором движке |
|---|---|
| персона (системный промпт, канал, артефакт) | переносится: тот же текст в `--append-system-prompt` |
| приватный режим | переносится частично: `--tools`/`--disallowedTools`, deny-правила |
| экстрактор/уборщик памяти | нет аналога; либо сервисный фоновый процесс, либо не включать |
| эскалация модели | у Claude Code свои `--model`/`--fallback-model`; наша логика не переиспользуется |
| субагенты | у Claude Code `Task` и `--agents`, семантика другая; наши отчёты о детях не совпадут |
| веб-поиск | `WebSearch`/`WebFetch` у Claude Code свои; наш роутер не задействован |
| control-panel, clock | переносятся как текст/промпт или теряются в beta |

Вывод: для beta честно объявить «Claude Code — без нашей памяти-экстрактора, без
эскалации, без субагентов Икара». Иначе получится движок, который выглядит как Икар, но
не помнит и не умеет половину.

## Выбор движка: разговор, не сообщение

- `ChatRecord.engine?: 'pi' | 'claude-code'` (старые записи без поля = `pi`).
- Выбор — при создании разговора (кнопка/селект в панели) и дефолт из конфига
  (`engines.default`). Для Telegram/API — тоже на разговоре.
- Смена посреди треда: команда «новый движок в этом разговоре» добавляет **эпоху**:
  `sessions[]` уже есть (`SessionEpoch`), добавляем `engine` в эпоху. Новая эпоха = новый
  процесс, новый транскрипт, бейдж в ленте. Старые сообщения не переписываются.
- Сообщение-уровневый выбор («вот это прогони Клодом») отвергаю для MVP: у движка
  состояние (процесс, сессия, контекст, права), и переключение на каждом сообщении — это
  либо потеря контекста, либо два процесса на разговор. Если очень нужно — это
  «one-shot ход другим движком» отдельной командой, без смены движка разговора.

## UI: кто отвечает

- **Заголовок разговора**: бейдж `pi` / `claude-code` рядом с workspace; у эпох —
  разделитель «движок: claude-code».
- **Лента**: у каждого ответа (или у эпохи) метка движка; при смене — разделитель, как
  сейчас у `/clear`.
- **Список чатов**: маленькая иконка/буква движка; иначе непонятно, кому предъявлять.
- **Трассировка**: первый шаг/notice хода начинается с `engine`, чтобы в истории было
  видно, кто отвечал, даже если сообщение одно.
- **API/Telegram**: `engine` в summary и в тексте ошибки; для OpenAI-фасада — в
  `model` (`icarus` / `icarus-claude`), иначе внешний клиент не отличит.

## Что НЕ делать

- Не запускать Claude Code в `HOME` человека и не тащить его плагины/хуки в сервис.
- Не парсить интерактивный TUI и не поднимать PTY: только `-p` + `stream-json`.
- Не эмулировать pi-RPC поверх Claude Code и не подменять протокол провайдера
  прокси-переходником: чинится не то место, ломается контракт.
- Не включать `--dangerously-skip-permissions` в общем случае: права выдаём списком
  инструментов, как сейчас `--exclude-tools` в приватном режиме.
- Не обещать «память как была»: экстрактор — расширение pi, его надо переписать.
- Не вливать второй движок без бейджа в UI: история с двумя движками без меток — это
  потерянное «кому предъявлять».

## Открытые вопросы (мерить до кода)

1. **Abort**: есть ли в stream-json вход управления прерыванием, или только SIGTERM +
   `--resume`? От этого зависит `interrupt()` и «новое сообщение поверх хода».
2. **MCP OAuth**: принимает ли `--mcp-config` наши заголовки на каждый запрос; работает ли
   `--strict-mcp-config` с http-серверами так же, как с stdio.
3. **Права на память**: как в `--settings` запретить запись в `/workspaces/.icarus/memory`
   (deny-правила/permission-mode), не отнимая чтение.
4. **Стоимость**: считать по `usage` своих токенов, а не по `total_cost_usd`; нужен
   счётчик на разговор, как у pi (`get_session_stats`).
5. **Версия**: зафиксировать CLI в образе (как `PI_VERSION`), иначе события поедут.
6. **Модель**: `[claude-code:unrecognized_model]` — косметика или ломает выбор модели в
   будущих версиях; проверить на 2–3 версиях.

npm install @anthropic-ai/claude-code   # вне репозитория, как в эксперименте
node tools/harness-probe/probe.mjs \
  --claude ./node_modules/.bin/claude \
