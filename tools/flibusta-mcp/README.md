# flibusta-mcp — книги во Флибусте

MCP-сервер на stdio: агент ищет книги, смотрит форматы и — отдельным инструментом
с подтверждением — скачивает файл. Устроен как соседний `tools/artifacts-mcp`:
один файл `server.mjs`, только встроенные модули Node, никаких зависимостей.

## Почему OPDS, а не только HTML

У Флибусты нет API по ключу, но есть **OPDS** — каталог для читалок. Он отдаёт
Atom/XML: название, автора, аннотацию, размер и ссылки на форматы. Поиск идёт
через него, HTML — запасной путь (и единственный для страницы книги:
`/opds/book/<id>` не существует, на любой id сервер отвечает корневым фидом).
У запасного зеркала `flibusta.club` OPDS нет вовсе (404), зато HTML-поиск работает —
поэтому путей два.

## Инструменты

| Инструмент | Что делает | Пишет на диск |
| --- | --- | --- |
| `book_search(query, by, limit)` | поиск по названию/автору; `by: "author"` — сначала автор, потом его книги | нет |
| `book_info(id)` | авторы, жанры, размер, форматы (fb2/epub/mobi), аннотация | нет |
| `book_download(id, format, confirm)` | скачать выбранный формат; без `confirm: true` отказ | да |
| `library_list()` | мини-реестр скачанного | нет |
| `mirror_status()` | какие зеркала живы и какое отвечает сейчас | нет |

Формат по умолчанию — `fb2`: это исходник библиотеки, `epub`/`mobi` конвертер
сайта собирает на лету и иногда бывает занят. `fb2` приходит архивом `.fb2.zip`
(внутри один `.fb2`) — так его и сохраняем, читалки открывают такой архив как книгу.

## Куда сохраняется

`FLIBUSTA_SAVE_DIR`, по умолчанию `$ICARUS_HOME/incoming` (в контейнере это
`/workspaces/.icarus/incoming` — папка вложений, откуда файл видит и панель, и
Telegram), иначе `./incoming` от текущего каталога. Имя файла человеческое:
`Автор - Название.формат`. Рядом лежит `library.json` — мини-реестр: id, название,
автор, формат, размер, дата, зеркало. Никакого Calibre: реестр читается глазами и
правится руками. Битый `library.json` не мешает скачивать — он откладывается в
`library.json.broken-<время>`, а реестр начинается заново.

## Настройки

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `FLIBUSTA_MIRROR` | `https://flibusta.is` | основное зеркало |
| `FLIBUSTA_MIRRORS` | `flibusta.site,flibusta.club` | запасные через запятую |
| `FLIBUSTA_TIMEOUT_MS` | `12000` | таймаут одного запроса страницы |
| `FLIBUSTA_DOWNLOAD_TIMEOUT_MS` | `180000` | таймаут скачивания файла |
| `FLIBUSTA_MAX_BYTES` | `26214400` (25 МБ) | лимит размера файла |
| `FLIBUSTA_SAVE_DIR` | `$ICARUS_HOME/incoming` | куда класть книги |
| `FLIBUSTA_LIBRARY` | `<save dir>/library.json` | файл реестра |

## Ошибки — три разных, и они не склеиваются

- **«Ничего не найдено»** — выдача разобралась и она пустая. Это ответ.
- **«Парсер сломался: …»** — страница пришла, но разметка не та (сайт переехал).
  В тексте сказано, какой именно маркер не нашёлся, и какие зеркала пробовали.
- **«Зеркала не ответили: …»** — сеть/зеркала, с причинами по каждому.
- Отдельно: неверный id книга не роняет парсер — сайт подменяет такую страницу
  поиском, поэтому ответ «зеркало отдало не книгу, а „Книги по названию …“».

## Тесты

```bash
./script/test packages/service/test/flibusta-mcp.test.ts
```

Тесты поднимают сервер отдельным процессом и подсовывают ему фейковое HTTP-зеркало
на `127.0.0.1`: фикстуры в `fixtures/` сняты с живой Флибусты 09.11.2026 дословно
(OPDS-поиск, пустая выдача, фид автора, страница книги, «не книга» по неверному id,
сломанный OPDS и сменившаяся вёрстка книги). В сеть тесты не ходят.

## Грабли

- У `flibusta.club` нет OPDS (404), у `flibusta.is`/`flibusta.site` есть.
- Некоторые фиды авторов на `flibusta.is` отвечают не сразу (десятки секунд) —
  поэтому у каждого запроса свой таймаут, а один «тяжёлый» автор не отменяет
  выдачу остальных.
- `/opds/author/<id>` — это НАВИГАЦИЯ («Об авторе», «Книги по сериям»), книги
  лежат в `/opds/author/<id>/alphabet`. Парсер не путает навигацию с книгами и
  честно ругается, если в фиде нет ни одной книги.
- Скачивание — это трафик и запись на диск: без `confirm: true` сервер отказывает,
  а лимит размера проверяется и по `content-length`, и по ходу потока (обрезанный
  файл удаляется).
