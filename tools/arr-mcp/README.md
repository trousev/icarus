# arr-mcp

MCP-сервер (stdio) для **кинозала**: Radarr (фильмы) и Sonarr (сериалы). Без
внешних зависимостей — только Node.js и HTTP API `*arr`.

Главная мысль сервера — не «скачать по интонации». Поиск, коллекция, очередь,
диски, профили качества и корневые папки **только читают**. Заказ файла — один
отдельный инструмент `arr_add`, и он выполняется только с `confirm: true`, то
есть после явного «добавь/закажи/скачай» от человека.

## Инструменты (8)

| Инструмент | Что делает |
|---|---|
| `arr_status` | настроен ли Radarr/Sonarr, отвечают ли, какая версия |
| `arr_lookup` | поиск в каталоге: год, рейтинг, описание, «уже в коллекции»; ничего не заказывает |
| `arr_collection` | что уже добавлено: размер, файл есть или только наблюдается |
| `arr_queue` | очередь загрузок: проценты, остаток, ошибки |
| `arr_disk` | свободное место на дисках сервера |
| `arr_quality_profiles` | профили качества, прочитанные с сервера |
| `arr_root_folders` | корневые папки, прочитанные с сервера |
| `arr_add` | **ЗАКАЗ ФАЙЛА**: add + поиск загрузки, только с `confirm: true` |

Профили и папки сервер не выдумывает: он берёт их из `/api/v3/qualityprofile` и
`/api/v3/rootfolder` уже настроенного Radarr/Sonarr. Если профиль или папка
одни — берёт их; если несколько — честно просит выбрать id/путь, а не угадывает.

## Настройка

Ключи — **только из окружения**, не из конфиг-файла и не из git:

| Переменная | Смысл |
|---|---|
| `ARR_RADARR_URL` | адрес Radarr, например `http://192.168.1.10:7878` |
| `ARR_RADARR_KEY` | API Key: Radarr → Settings → General → API Key |
| `ARR_SONARR_URL` | адрес Sonarr, например `http://192.168.1.10:8989` |
| `ARR_SONARR_KEY` | API Key: Sonarr → Settings → General → API Key |
| `ARR_TIMEOUT_MS` | таймаут одного запроса, по умолчанию 8000, от 200 до 60000 |

Можно настроить только Radarr или только Sonarr: ненастроенный сервер — это не
падение, а понятный ответ «не настроен».

### В панели Икара — рецептом

Руками ничего настраивать не нужно: **панель → MCP → Рецепты → «Кинозал
(Radarr/Sonarr)» → «Добавить»**. Рецепт подставляет команду
(`node /opt/icarus/tools/arr-mcp/server.mjs`), транспорт и имена четырёх
переменных; человек вписывает только адреса и ключи. Можно заполнить только
пару Radarr или только пару Sonarr — второй сервис ответит «не настроен».

Сервер личный, а не общий: он приезжает ленивым (`lifecycle: lazy`), включается
себе одним переключателем и ключи хранит в `dataDir/mcp/credentials.json`
(0600), а не в описании сервера. Общего блока `mcp.arr` в `config.yaml` больше
нет: рецепт заменяет ручную настройку.

### Где живёт сервер

Код монтируется в контейнер агента из репозитория:
`tools/arr-mcp` → `/opt/icarus/tools/arr-mcp` (только чтение). Radarr/Sonarr при
этом остаются отдельными сервисами: этот MCP — клиент, а не ещё один контейнер.
Адрес в `ARR_RADARR_URL` должен быть доступен **из контейнера агента**; если Radarr
поднят на хосте, это адрес хоста в docker-сети, а не `127.0.0.1`.

## Два способа запуска

**stdio** — основной: сервер поднимает сам pi внутри контейнера агента, ключи
приходят из рецепта в панели (там они лежат в 0600-файле credentials).

**HTTP (Streamable HTTP)** — если удобнее держать сервер отдельным контейнером
рядом с arr-стеком:

```bash
ARR_RADARR_URL=http://radarr:7878 ARR_RADARR_KEY=... \
  node server.mjs --http 8799
# http://127.0.0.1:8799/mcp
```

По умолчанию слушается только `127.0.0.1`. Наружу — только осознанно
(`--host 0.0.0.0`) и обязательно с токеном: `ARR_HTTP_TOKEN` заставляет сервер
требовать `Authorization: Bearer <токен>`. Иначе любой, кто дотянется до порта,
сможет вызывать `arr_add` — то есть заказывать файлы.

## Проверка

```bash
node tools/arr-mcp/test.mjs      # 17 проверок против фейкового Radarr/Sonarr на node:http
```

Тесты не ходят в сеть и не требуют настоящего Radarr: поднимается локальный
HTTP-сервер, проверяются `X-Api-Key`, маршруты `/api/v3/...`, отказ без
`confirm`, заказ с `confirm`, чтение профилей/папок, 401, таймаут и «не настроен».

Формы запросов сверены с OpenAPI Radarr/Sonarr (`src/Radarr.Api.V3/openapi.json`,
`src/Sonarr.Api.V3/openapi.json` в их репозиториях): `GET movie/lookup`,
`GET movie/lookup/tmdb`, `GET series/lookup`, `POST movie`, `POST series`,
`GET queue`, `GET diskspace`, `GET qualityprofile`, `GET rootfolder`,
`GET system/status`, ключ в заголовке `X-Api-Key`.

## Грабли

- Radarr при добавлении сам тянет метаданные с TMDB по `tmdbId`, Sonarr — с
  TVDB по `tvdbId`. Без доступа к этим базам у самого Radarr/Sonarr `arr_add`
  вернёт ошибку сервера — это его настройка, не MCP.
- `arr_add` с `search: false` добавляет только наблюдение: файл не заказывается,
  и это прямо написано в ответе.
- Ответы `*arr` при ошибках бывают и массивом `{propertyName, errorMessage}`, и
  объектом `{message}` — сервер разбирает оба и показывает текст сервиса как есть.
