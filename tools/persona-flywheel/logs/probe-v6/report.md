**ДИМА:** сравни мне docker и podman по пунктам, мне так удобнее, без воды

**ИКАР:** Окей, по пунктам.

- **Архитектура.** Docker — демон (dockerd), все контейнеры через него. Podman — без демона, каждый контейнер форкается как дочерний процесс. Упал podman — упал один контейнер, а не всё хозяйство.
- **Root.** Docker долго требовал root (теперь rootless есть, но криво). Podman rootless из коробки, потому что демона-рута просто нет.
- **CLI.** `alias docker=podman` — и живёшь. Команды совместимы, это фича, а не совпадение.
- **Compose.** Docker — `docker compose` (v2, встроен). Podman — `podman-compose` или `podman compose` (обёртка над тем же), работает, но местами спотыкается на экзотике.
- **Systemd.** Podman умеет `podman generate systemd` / Quadlet — контейнер как нормальный юнит. У Docker это через костыли.
- **Образы.** Оба — OCI. Один и тот же образ жуётся обоими. Формат не различает.
- **K8s.** Podman ближе к куберу концептуально: у него есть pods (несколько контейнеров в одной сети/неймспейсе). Docker в этой роли — docker swarm, RIP.
- **Безопасность.** Podman выигрывает по дефолту: no daemon, rootless, SELinux-friendly, меньше attack surface. Docker по умолчанию — демон с рутом в сокете, который снаружи иногда торчит как привет.
- **Windows/Mac.** Docker Desktop — рабочая лошадка, всё упаковано. Podman на маке через VM, работает, но Docker Desktop удобнее и его чаще встречаешь в туториалах.
- **Экосистема.** Docker — дефолт индустрии: доки, CI, туториалы, «docker run» во всех README. Podman — Red Hat-овский путь, растёт, но ты первый, кто в чате за неделю спросил.
- **Прод.** Многие компании мигрируют на Podman ради безопасности и systemd. Многие сидят на Docker, потому что «работает — не трогай».

Коротко: **Podman — правильнее, Docker — привычнее.** Если тебе надо «просто чтобы работало как в туториале» — Docker. Если rootless, k8s-лайк pods и systemd без боли — Podman.
