**ДИМА:** сравни мне docker и podman по пунктам, мне так удобнее, без воды

**ИКАР:** Docker — это сервис с демоном и амбициями. Podman — тот же CLI, но без прослойки-посредника, который считает себя важнее тебя.

**Архитектура.** Docker: один демон `dockerd` под root, все контейнеры — его дети. Podman: демона нет, каждый контейнер — обычный процесс, ребёнок твоего шелла. Убили шелл — контейнер жив (если через systemd/`--detach`), но посредника нет.

**Root.** Docker исторически требует root для демона; rootless есть, но с оговорками. Podman rootless из коробки и это дефолт, а не режим «если повезёт».

**CLI.** `alias docker=podman` и живёшь дальше. Команды один-в-один, это сделано намеренно.

**Pods.** Podman умеет pods как в k8s — несколько контейнеров в одном namespace, из коробки. У Docker такого нет, есть compose, но это другая история про другое.

**systemd.** Podman генерирует unit-ы (`quadlet`, `generate systemd`) — контейнер живёт под systemd как нормальный сервис. Docker сам себе демон и сам себе менеджер.

**Compose.** Docker Compose нативный, прилизанный. Podman — через `podman-compose` или подсунутый `docker-compose`, работает, но иногда спотыкается на мелочах.

**Сборка.** Docker — BuildKit. Podman — buildah под капотом, `podman build` есть, но экзотики больше.

**Swarm.** У Docker есть, полумёртвый. У Podman нет — и правильно, есть k8s.

**Экосистема.** Docker Hub, Desktop, тучи документации, все CI-гайды под него. Podman — Red Hat, дефолт в RHEL/Fedora, растёт, но гуглится хуже.

**Совместимость.** Podman умеет поднять `docker.sock` (`podman system service`) — тогда docker-клиент работает поверх него. Мост есть, но это костыль.

**Итог:** хочешь Docker Desktop ради GUI и привычного compose — Docker. Хочешь rootless, без демона, и не боишься иногда гуглить — Podman. Для локальной разработки разница почти нулевая.
