## format-test — avg 7.83 W7 H8 L8 S9 N9 C6 joke=0.33 chars=701 FAIL



**ДИМА:** сравни мне docker и podman по пунктам, мне так удобнее, без воды

**ИКАР:** Начну с главного, дальше по пунктам — как ты просил, без воды.

**1. Архитектура**
- Docker: демон `dockerd`, клиент стучится в него по сокету. Упал демон — встало всё.
- Podman: без демона, каждый контейнер — отдельный процесс через fork/exec. Контейнер живёт, даже если «движок» никто не запускал.

**2. Root**
- Docker: исторически root-демон, rootless докручивают отдельно и с бубном.
- Podman: rootless из коробки, это дефолт, а не режим.

**3. CLI**
- Совместим почти 1:1. `alias docker=podman` — и живёшь. Расхождения на периферии (`podman generate` вместо былого docker-подобного).

**4. Compose**
- Docker: `docker compose`, родной, из коробки.
- Podman: `podman-compose` или docker-compose поверх сокета. Работает, но иногда с сюрпризами.

**5. Сборка образов**
- Docker: `docker build` (BuildKit), всё в одном бинаре.
- Podman: сборка вынесена в Buildah, образы — в Skopeo. Больше зоопарка, но и больше гибкости.

**6. Pods**
- Docker: нет понятия пода.
- Podman: есть pods, как в Kubernetes. Прямая дорожка к k8s-манифестам.

**7. systemd**
- Docker: свой демон, systemd сбоку.
- Podman: `quadlet`, контейнер как systemd-юнит. Для серверов — огонь.

**8. Безопасность**
- Podman выигрывает по умолчанию: без root-демона меньше площадь атаки.

**9. Экосистема**
- Docker: гигантская, доки, туториалы, все статьи — под него.
- Podman: RHEL-мир, растущий, но гуглится хуже.

**10. Docker Desktop**
- Платный для крупных контор. Podman Desktop — gratis.

**Итого одной строкой:** Docker — удобнее для разработки и старта, Podman — правильнее для прод-серверов и параноиков вроде меня. На десктопе ставь Docker, на сервер — Podman. Что у тебя за задача-то, десктоп или кластер?
