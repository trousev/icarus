# artifacts-mcp

MCP-сервер (stdio), который учит агента артефактам: куда класть готовые вещи,
откуда их брать, как прочитать `index.ai.md` вместо HTML и как получить публичную
ссылку. Без внешних зависимостей — только Node.js.

## Что такое артефакт

Папка `artifacts/<slug>/` в текущей рабочей папке (workspace):

```text
artifacts/plan-na-chetverg/
  index.md          # то, что видит человек: index.html | index.md | index.png|jpg|svg
  index.ai.md       # обязательное описание для ИИ
  images/standup.png
```

Тип определяется по index-файлу. Остальные файлы — ассеты, ссылки внутри HTML
относительные. `index.ai.md` — не для человека: заголовок H1, о чём артефакт,
что внутри, что можно менять. По нему модель понимает содержимое, не разбирая
HTML и не глядя на картинку.

## Инструменты (4)

| Инструмент | Назначение |
|---|---|
| `artifact_list` | список артефактов: название, тип, размер, описание для ИИ, ссылки; поиск по тексту |
| `artifact_read` | `index.ai.md` + список файлов + ссылки; у markdown — ещё и сам текст |
| `artifact_link` | ссылка: по умолчанию внутренняя (в панели); `public: true` — публичная с `publicId` и `?bare=1` |
| `artifact_check` | структура: есть ли index, нет ли второго, на месте ли `index.ai.md` |

Создавать артефакты отдельным инструментом не нужно: это обычные файлы, и pi
умеет их писать. Сервер не дублирует файловые операции — он даёт знание,
которого у файловых инструментов нет.

## Запуск

```bash
cd /workspaces/talk                     # cwd = workspace, в нём лежит artifacts/
node /opt/icarus/tools/artifacts-mcp/server.mjs     # stdio
```

Сервер читает переменные окружения:

| Переменная | Зачем |
|---|---|
| `ICARUS_URL` | внешний адрес панели; из него собираются публичная ссылка и ссылка в панели |
| `ICARUS_USER_ID` | чей workspace; без него публичная ссылка не создаётся |
| `ICARUS_WORKSPACE` | имя workspace; по умолчанию — `basename(cwd)` |

`ICARUS_URL` и `ICARUS_USER_ID` сервис уже кладёт в контейнер человека
(`containerEnv`), поэтому в конфиге MCP их прописывать не надо.

## Подключение к Икару

```yaml
mcp:
  artifacts:
    command: node
    args: ['/opt/icarus/tools/artifacts-mcp/server.mjs']
    lifecycle: lazy
    hidden: true
    description: "Артефакты: готовые страницы, документы и картинки для человека — папка artifacts/ в рабочей папке"
```

`hidden: true` убирает сервер из раздела MCP и запрещает выключать: это встроенное
умение. `lifecycle: lazy` — главное: инструкции и инструменты не занимают промпт
каждого разговора. В `AGENTS.md` едет только короткое описание-триггер; когда
человек заговорит об артефактах, модель зовёт `mcp_connect` и получает полные
инструкции в `instructions` MCP-хендшейка.

## Публичная ссылка

`artifact_link` с `public: true` пишет в папку скрытый `.artifact.json`. Без `public: true`
он ссылку не публикует, а отдаёт внутреннюю — её и надо давать человеку по умолчанию:

```json
{ "version": 1, "publicId": "случайные-18-байт", "createdAt": "…", "updatedAt": "…" }
```

Ссылка выглядит как `<ICARUS_URL>/a/<человек>/<workspace>/<артефакт>/<publicId>/`.
`publicId` случаен, поэтому имя папки ничего не выдаёт; отозвать ссылку — значит
удалить `publicId` (в панели). По умолчанию ссылка открывает артефакт внутри
панели, `?bare=1` — без панели, а прямой путь на index-файл — сам файл.

## Проверка

```bash
node tools/artifacts-mcp/test.mjs
```

Тест поднимает сервер отдельным процессом, делает настоящий `initialize` и
проверяет инструменты на временной рабочей папке: список, чтение, ссылку,
структуру и ошибки. Модель, сеть и докер не нужны.
